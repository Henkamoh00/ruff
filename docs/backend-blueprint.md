# خلاصة بناء الباكند للمشروع الجديد

> الفكرة العامة فقط. كل بند اختياري: نعتمده إذا احتجناه، ونتركه إذا لم نحتجه.

---

## 1) تذكير الأسرار (لا تنسَ)

- **`.env` لا يُرفع أبداً.** أضفه إلى `.gitignore` و`.dockerignore` قبل أول commit.
- **`.env.example` يُرفع**: أسماء المتغيرات فقط بقيم وهمية، ويُحدَّث كلما أُضيف متغير.
- **الأسرار الحقيقية** (JWT، قاعدة البيانات، السحابة) تُولَّد لكل بيئة ولا تُشارك بين التطوير والإنتاج.
- **إن سُرّب سرّ مرة واحدة** (حتى داخل zip أو لقطة شاشة): دوّره فوراً. حذفه من الملف لا يكفي.
- **التطبيق يفشل عند الإقلاع** إذا غاب سرّ مطلوب أو كان ضعيفاً (طوله أقل من 32 بايت). استخدم `pydantic-settings`.
- **مفاتيح منفصلة** لكل غرض (JWT، التوقيعات، التشفير). لا مفتاح واحد لكل شيء.
- **افحص التاريخ** بأداة مثل `gitleaks` قبل أي رفع، وفعّلها كـ pre-commit hook.

## 3) الهيكلة (فكرة عامة)

```
app/
  core/      الإعدادات، الأمان، السجلات، الأخطاء
  db/        base، mixins (الحذف الناعم)، session
  audit/     تتبع الأثر
  auth/      الدخول، الجلسات، CSRF
  modules/   حزمة لكل مجال: models / schemas / service / router
migrations/
.env.example
```

- **الراوتر** يتحقق ويفوّض فقط. **الـ service** فيه المنطق والاستعلامات.
- **كل endpoint بـ `response_model`**، فلا يُرجع كائن ORM خاماً ولا يسرّب حقولاً حساسة.
- **Naming Convention** في `MetaData` ليبقى الـ Alembic متوقّعاً.

## 4) المصادقة

- **JWT قصير** (Access حوالي 15 دقيقة) في **كوكي `HttpOnly` + `Secure` + `SameSite=Lax`**.
  - لا نخزّن التوكن في `localStorage` أبداً (يحميه من XSS).
  - **اجعل الواجهة والـ API تحت نفس الموقع (same-site)**، مثل `app.example.dz` و`api.example.dz`، حتى تكفي `Lax`. استعمال `None` يُضعف الحماية ويُترك للضرورة القصوى.
- **Refresh Token**:
  - قيمة عشوائية معتمة، لا JWT.
  - تُخزَّن في القاعدة كـ **hash** فقط.
  - تُدوَّر عند كل استخدام.
  - إعادة استخدام توكن مُدوَّر خارج نافذة سماح قصيرة (حوالي 10 ثوانٍ) تُلغي عائلة الجلسة كلها.
  - يُلغى كل شيء عند تغيير كلمة المرور أو تعطيل الحساب.
- **حقول JWT**: `sub` (معرّف رقمي) و`jti` و`exp` و`iss` و`aud` و`typ`. نرفض `alg=none` ونثبّت الخوارزمية.
- **التحقق من القاعدة في كل طلب** (مفعّل؟ محذوف؟ الدور؟). بهذا يسري التعطيل فوراً.
- **bcrypt بدل Argon2id**: كافٍ وآمن عند ضبطه جيداً.
  - `rounds` لا تقل عن 12.
  - **حدّ 72 بايت**: ارفض ما زاد عنها (أو مرّر كلمة المرور بـ SHA-256 ثم base64 قبل bcrypt). الإصدارات الحديثة ترفعه كخطأ.
  - **نفّذه خارج حلقة الأحداث** (`asyncio.to_thread`) لأنه حسابي ثقيل ويحجب الـ async.
  - **تحقق وهمي** عند غياب المستخدم لإخفاء فرق التوقيت.
  - **ننتقل إلى Argon2id فقط** إذا فرضه معيار امتثال أو احتجنا مقاومة GPU أشد.
- **صلاحيات** (RBAC) فقط إذا كان للتطبيق أدوار فعلية: دور وقائمة صلاحيات في القاعدة، مع قاعدة "لا تمنح ما لا تملك".

## 5) الحماية من XSS

- **الكوكيز `HttpOnly`** فلا يقرؤها JavaScript حتى مع وجود ثغرة.
- **ترويسة `Content-Security-Policy` صارمة**: `default-src 'self'`، بلا `unsafe-inline`، مع nonce عند الحاجة.
- **ترويسات إضافية**: `X-Content-Type-Options: nosniff` و`Referrer-Policy` و`X-Frame-Options: DENY` (أو `frame-ancestors` في CSP) و`Permissions-Policy`.
- **الـ API يُرجع JSON فقط** مع `Content-Type` صحيح. لا يُنتج HTML من مدخلات المستخدم.
- **تحقق صارم من المدخلات** (Pydantic): الأنواع والأطوال وقوائم القيم المسموحة (Enum).
- **عند عرض HTML** في الواجهة: لا `v-html` / `innerHTML` بمحتوى المستخدم. وإن لزم فمعقّم مثل DOMPurify.
- **رفع الملفات** (إن وُجد): تحقق من النوع والحجم، وأعد تسمية الملف، وقدّمه من نطاق منفصل بلا تنفيذ.

---

## 6) الحماية من CSRF

- `SameSite=Lax` خط الدفاع الأول، **لكنه لا يكفي وحده** (لا يغطي هجمات من نطاقات فرعية أخرى ولا GET الذي يغيّر الحالة).
- **أضف نمط double-submit**:
  - كوكي CSRF يقرؤه JS (غير HttpOnly).
  - ترويسة `X-CSRF-Token` تُرسل مع كل طلب غير آمن (POST / PUT / PATCH / DELETE).
  - يقارَن الاثنان بمقارنة ثابتة الزمن (`secrets.compare_digest`).
  - يُنفَّذ كـ **ASGI middleware خالص** لا `BaseHTTPMiddleware`.
  - يُستثنى فقط الدخول والخروج وما يحمل توقيعاً خاصاً (مثل webhooks).
- **لا تغيّر الحالة بـ GET أبداً.**
- **تحقق من `Origin` / `Host`** للطلبات غير الآمنة كطبقة إضافية.
- **CORS**: قائمة بيضاء صريحة بالأصول، مع `allow_credentials=True`، دون `*`.

## 7) Rate Limiting

- **مستويات**:
  - حدّ عام لكل IP.
  - حدّ صارم لمسارات الدخول والتسجيل واستعادة كلمة المرور (مثلاً 5 في الدقيقة لكل IP، ويُضاف حدّ لكل اسم مستخدم).
  - حدّ لكل مستخدم للكتابة والعمليات الجماعية.
- **التخزين في Redis** مع بديل في الذاكرة إذا سقط (الفشل مفتوح للحدود العامة، ومغلق لمسارات الدخول).
- **IP الحقيقي**: لا تثق بـ `X-Forwarded-For` إلا من الوكيل العكسي المعروف.
- **قفل مؤقت للحساب** بعد محاولات فاشلة متكررة، مع تأخير متصاعد. وسجّل كل محاولة فاشلة.
- **ردود 429** بترويسة `Retry-After`.
- **حدّ لحجم الطلب** (body size) ومهلة للطلبات، لحماية من الاستنزاف.

## 8) تتبع الأثر (Audit Trail) والسجلات (Logs)

هما شيئان مختلفان ونحتاج الاثنين:

| | Audit Trail | Logs |
|---|---|---|
| الغرض | من فعل ماذا ومتى (مساءلة) | تشخيص وتشغيل (أعطال وأداء) |
| المكان | جدول في القاعدة | stdout بصيغة JSON ← مجمّع سجلات |
| الاحتفاظ | طويل ولا يُعدَّل | قصير ويُدوَّر |

**Audit Trail**
- **تسجيل تلقائي** عند الإنشاء والتعديل والحذف والاستعادة عبر مستمع على الجلسة (`after_flush`)، بدل استدعاء يدوي في كل endpoint.
- **داخل نفس المعاملة**: تنجح العملية مع أثرها أو تفشلان معاً.
- **للتعديل نخزّن الفرق** `{حقل: [قديم, جديد]}`. وللحذف لقطة من السجل.
- **الفاعل** (المستخدم، IP، `request_id`) يُحمل في `ContextVar`.
  - فخ مهم: الـ dependency الذي يضبطه يجب أن يكون `async def`.
- **الحقول الحساسة تُقنَّع** (كلمات المرور، التوكنات).
- **أحداث الأمان تُسجَّل أيضاً**: دخول ناجح وفاشل، خروج، تغيير كلمة مرور، إلغاء جلسات، رفض صلاحية، ضغط على الحد (429).
- **الجدول للإلحاق فقط**: لمستخدم التطبيق INSERT وSELECT فقط، بلا UPDATE ولا DELETE.
- **`entity_id` نص بلا مفتاح أجنبي** ليبقى الأثر بعد حذف السجل.

**Logs**
- **structlog بصيغة JSON** مع `request_id` في كل سطر، ويُمرَّر الـ `request_id` في ترويسة الرد.
- **لا أسرار ولا كلمات مرور ولا توكنات** ولا بيانات شخصية كاملة في السجلات.
- **مستويات واضحة**: ERROR للأعطال، WARNING لأحداث الأمان المشبوهة، INFO للحدث العادي.
- **لا `print`**.

## 9) الحذف الناعم (إن احتجناه)

- **Mixin واحد**: `deleted_at` و`deleted_by_id` (والسبب اختيارياً).
- **فلترة تلقائية** على مستوى الجلسة (`with_loader_criteria`) حتى لا ينسى أحد الشرط، مع خيار صريح لعرض الأرشيف.
- **فهارس فريدة جزئية** `WHERE deleted_at IS NULL` حتى يمكن إعادة استخدام الأسماء بعد الحذف.
- **الاستعادة** تُرجع 409 إذا تعارضت مع سجل نشط. وحذف المحذوف مسبقاً يُرجع 404.
- **ما هو مالي أو قانوني لا يُحذف**: يُلغى أو يُعكس بقيد جديد.
- **Router Factory** يولّد (قائمة / حذف / أرشيف / استعادة / تاريخ) لأي كيان بدل التكرار.

## 10) الأداء و async

- **async مفيد هنا** (انتظار القاعدة وRedis وطلبات خارجية)، لذا نعتمده في الـ API والـ DB: `AsyncSession` + `psycopg` async.
- **لا تحجب حلقة الأحداث**: كل عمل حسابي ثقيل (bcrypt، PDF، معالجة صور، ضغط) يُنفَّذ بـ `asyncio.to_thread` أو في عملية مستقلة.
- **كل ترقيم صفحات في SQL** (LIMIT/OFFSET أو keyset)، وتحميل العلاقات بـ `selectinload` / `joinedload` لتفادي N+1.
- **فهارس** على أعمدة الفلترة والفرز، وأضف الفهارس المركّبة التي تخدم استعلامات الشاشات الفعلية.
- **المهام الدورية** (تنظيف التوكنات القديمة، الأرشفة) في عملية واحدة أو بقفل `pg_advisory_lock`، لا داخل كل worker.
- **القياس قبل التحسين**: لا نضيف cache أو تعقيداً إلا عند وجود بطء مُثبت.

## 11) بيانات وتشغيل (باختصار)

- **المال** `Numeric` مع `Decimal`، لا `float`.
- **الوقت** يُخزَّن UTC (`timestamptz`) ويُحوَّل للمنطقة المحلية عند العرض فقط.
- **التزامن**: `SELECT ... FOR UPDATE` للصفوف الحساسة، وقيود فريدة كخط أخير، وتحويل `IntegrityError` إلى 409.
- **التشغيل**: Docker متعدد المراحل بمستخدم غير root، خلف وكيل عكسي بـ HTTPS إلزامي (HSTS)، مع `/health` و`/ready`.
- **قاعدة البيانات**: مستخدم التطبيق بأقل صلاحيات، وحساب منفصل للترحيلات، ونسخ احتياطي مجرَّب الاستعادة.
- **الاعتماديات**: ثبّت الإصدارات (lock file) وافحصها دورياً (`pip-audit`) وحدّثها باستمرار.
- **وثائق API** (`/docs`) تُعطَّل أو تُحمى في الإنتاج.

## 12) ميزات نأخذها فقط عند الحاجة

| الميزة | متى نستخدمها |
|---|---|
| أدوار وصلاحيات (RBAC) | وجود أكثر من نوع مستخدم فعلياً |
| حذف ناعم | بيانات يجب استعادتها أو الاحتفاظ بأثرها |
| سجلات مالية للإلحاق فقط (ledger) | وجود أرصدة أو مدفوعات |
| توقيع HMAC لروابط عامة / QR | وجود مستند يُتحقق منه علناً |
| توليد PDF | وجود فواتير أو تقارير للطباعة |
| Redis | rate limit موزّع أو cache أو طابور |
| طابور مهام (arq / Celery) | أعمال طويلة أو مجدولة |
| 2FA | حسابات إدارية أو بيانات حساسة |
